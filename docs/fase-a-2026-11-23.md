## Etiquetado y entrenamiento

Sigue ampliando la captura observable sin reiniciar durante la Fase A. Para usar un tramo como etiqueta, un observador en el sitio registra inicio y fin de un intervalo homogéneo, estado `rain` o `no_rain`, un código de evento, un código de observador y la referencia de su evidencia. Conserva la hora con zona explícita (`-05:00` en Bogotá), sincronizada con el PC que recibe las muestras. Las horas sin observación o con incertidumbre quedan fuera de las etiquetas. El archivo de partida `C:\AgroEdge\output\evidencia\etiquetas-cabecera.csv` tiene solo el encabezado, listo para copiar al archivo privado de trabajo.

Programa nuevas sesiones de arranque cuando se autoricen pausas. Cerrar el puente por sí solo puede conservar el mismo ID de sesión. Para completar entrenamiento, validación y prueba, se necesitan capturas enteramente dentro de cada bloque, con 30 minutos de separación después de cada corte. Mantén el mismo código de evento si la lluvia cruza un reinicio. El mínimo operativo del piloto es diez ventanas y dos eventos independientes por clase en cada partición. Las sesiones extensas no sustituyen esa cobertura. El análisis previo con el CSV vacío confirmó cero ventanas etiquetadas y `ready: false`.

## Secuencia para la Fase B, después de autorización expresa

1. Desconecta **Adquisición por USB** desde el dashboard y conserva el servidor en marcha. Cierra cualquier monitor serial. Vuelve a comprobar el identificador del puerto si Windows lo reasigna.
2. Lee la Flash instalada con `esptool --chip esp32s3 --port COM8 read-flash 0 ALL <ruta-nueva.bin>`. Conserva la imagen en una carpeta privada, confirma que su tamaño coincide con la capacidad detectada y calcula SHA-256. Si la protección o un error impiden un respaldo utilizable, detén la carga y revisa la recuperación con el usuario.
3. Carga con `arduino-cli upload --port COM8 --fqbn $perfilOperativo --input-dir .venv/fase-a/candidato hardware/esp32_tinyml`. `$perfilOperativo` corresponde al campo `fqbn` de `build.options.json` del respaldo. Guarda la salida del cargador. En caso de fallo en sensores o en la salida serial, usa la imagen verificada de la misma placa y el procedimiento de escritura de Espressif, con confirmación antes de restaurar. [Espressif, carga desde archivos binarios](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/flashing-firmware.html)
4. Con el dashboard todavía desconectado del puerto, abre una sola sesión de diagnóstico para las seis lecturas y el benchmark. Guarda la evidencia fuera de Git. Después de que se cierre el diagnóstico, vuelve a conectar USB desde el dashboard a 115200 baudios y comprueba que la sesión `s3-…` guarda una `classification.source` igual a `ESP32`, con modelo `humidity-prototype-1` y `modelStatus` igual a `PRELIMINARY`. Ejecuta la auditoría de solo lectura y registra la primera ventana clasificada. Las lecturas de banco seguirán identificadas por su sesión y sin etiquetas de campo.
